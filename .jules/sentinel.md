## 2025-02-14 - SSRF and DNS Rebinding vulnerability in register endpoint
**Vulnerability:** The `/api/ivc/register` endpoint validated user-provided host URLs against standard private/loopback IPs, but relied entirely on string matching of standard IP ranges (like `127.`). It was susceptible to octal/hex conversions, IPv4-mapped IPv6 formats (like `::ffff:127.0.0.1`), and most importantly, DNS rebinding. The vulnerability allowed an attacker to register a local host endpoint for the server to ping, compromising internal services by exposing `localhost` directly.
**Learning:** Checking for DNS resolution IP requires utilizing robust IP range checks like `ipaddr.js` rather than naive string prefixes to handle alternative address syntaxes correctly. Furthermore, checking the IP is useless if we still perform the request to the original hostname, since DNS can change immediately after validation.
**Prevention:** Always use a verified library (like `ipaddr.js`) to parse and validate IP address types. Mitigate DNS rebinding by explicitly forcing `fetch` or other HTTP clients to connect directly to the validated IP address instead of the hostname. When making a request to an IP, manually re-attach the original `Host` header to preserve SNI/virtual hosting where necessary.

## 2026-08-21 - Reserved Channel Spoofing via Slash Prefix
**Vulnerability:** The direct posting endpoint in `server.ts` (`app.post("/*")`) captures the channel name by removing a single leading slash (`req.path.substring(1)`). If an attacker submitted a post request to a path with multiple leading slashes (e.g., `//test`), `channelRaw` became `/test`. Because `/test` doesn't begin with protected characters like `+`, the post was allowed through. However, channels prefixed with `/` are unassigned but reserved for future functionality, which allowed a malicious user to squat or manipulate reserved channel names.
**Learning:** Always validate downstream parsed/derived resource names. Stripping a character is a mutation; if a route acts as a catch-all mapping to a namespace, it is critical to implement explicit boundaries/validation on the resulting namespace string (e.g. `channelRaw`).
**Prevention:** Implement a strict validation check directly after extracting the resource name to ensure it doesn't violate namespace constraints, such as explicitly rejecting any channel name that still begins with a reserved character like `/`.
