## 2025-05-18 - Destructive Actions and Icon Buttons in Scheduled Tasks
**Learning:** Found that icon-only action buttons (like Delete and Pause) on scheduled tasks lacked `aria-label` attributes and keyboard focus indicators (`focus-visible`). Additionally, the destructive "Delete" action executed immediately without a confirmation prompt, which can lead to accidental data loss.
**Action:** When adding or reviewing icon-only buttons, especially in list items or repetitive components, always ensure `aria-label` and `focus-visible` classes are present. For any destructive actions (like delete), ensure a confirmation mechanism (like `window.confirm`) is in place.

## 2025-08-31 - Semantic Buttons for Clickable Header Elements
**Learning:** Found that the IVC Network Status, User Registry, and Manage Modes indicators in the header (`src/App.tsx`) were using non-semantic `div` tags with `onClick` handlers. This caused a major accessibility issue as they lacked keyboard navigation support and focus indicators. Additionally, adding static `aria-label`s to dynamic elements (like the network status which changes from "Connecting..." to "Connected" to "Offline") overrides their text content, causing screen readers to miss vital dynamic state information.
**Action:** Always prefer semantic HTML elements (like `<button>` for actions). When converting `div` to `<button>`, apply standard `focus-visible` classes (e.g., `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-indigo-500 focus-visible:ring-offset-1`) for visible keyboard navigation. Avoid assigning static `aria-label` attributes to elements that display dynamic text content unless you concatenate the dynamic state into the `aria-label`, to ensure screen readers announce the correct live state.
